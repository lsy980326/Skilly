# 로컬 실행 결과 수집

## 수집 범위

Skilly는 명시적으로 실행기를 거친 **프로세스 관측**을 AI 보고와 분리해서 저장한다.
명령·인자·결과를 JSON으로 받아 실행 사실로 등록하는 MCP 쓰기 도구는 제공하지 않는다.
조회 도구 `memory_list_executions`와 기존 기록의 `memory_get_evidence.executions`로 읽는다.
로컬 파일·가져온 묶음은 변조 가능한 자료이므로 이 출처는 암호학적 인증이나 기능 검증이 아니다.

2026-10-22 [공식 Codex Hooks 문서](https://learn.chatgpt.com/docs/hooks)에서
`PostToolUse`와 Bash/unified exec 결과 경로, 프로젝트·훅 정의별 신뢰가 필요함을 확인했다.
설치된 CLI `0.163.0-alpha.10.2`의 `features list`도 `hooks stable true`를 표시했다.
지원 표시는 실제 훅 설치·승인·이벤트 수집 성공과 다르다. 이 기능은 훅·신뢰·사용자 설정을
수정하지 않는다. 일반 도구 호출 전체나 대화·환경 파일·전사 파일을 읽지 않는다.

## 실행 순서

평소처럼 MCP로 프로젝트를 식별하고 작업을 시작한다. 받은 작업 ID와 기존 변경 기록 ID를
사용해 승인된 로컬 검사 명령을 실행한다. DB 경로를 모르면 사적 설정을 읽거나 추측하지 않는다.
이 실행기는 MCP 장애나 신뢰 결정을 우회하는 기록 경로가 아니다.

```sh
npm run build
node dist/runtime/local/main.js exec \
  --db /absolute/test/memory.sqlite \
  --project /absolute/test/project \
  --run-id 작업_UUID --record-id 변경기록_UUID \
  --timeout-ms 60000 -- node --test tests/example.test.mjs
```

`--record-id`는 생략할 수 있으며, 있으면 같은 프로젝트·작업에 속해야 한다.
프로젝트 식별 파일의 저장소·환경과 작업 범위를 대조하고 작업이 열려 있는지 확인한다.
**시작 항목 저장이 성공한 뒤** 지정 프로젝트 폴더에서 명령을 직접 실행한다. 셸 해석은 하지 않는다.
명령 실행 권한이나 네트워크 권한을 새로 부여하는 도구가 아니며 호출한 환경의 권한을 따른다.
현재 macOS/Linux를 지원한다. Windows와 Codex 훅 자동 설치는 포함하지 않는다.

실행기는 자식 표준 출력·오류를 터미널에 재출력하거나 DB에 보관하지 않는다.
실행 영수증 JSON만 출력하며 기본 제한은 60초, 선택 범위는 10ms–1시간이다.
명령 종료 코드를 반환하고 시작 실패는 127, 시간 제한은 124, 사용자 중단은 130이다.
장기 실행 서버를 관리하는 명령으로 사용하지 않는다.

## 저장하는 사실과 저장하지 않는 정보

| 저장 | 의미 |
|---|---|
| 실행·프로젝트·작업 ID, 선택한 기록 ID | 실행 관측과 AI 보고의 연결 |
| 실행 파일의 짧은 이름, 명령 해시 | 인자·절대 경로·환경 원문은 미보관 |
| 시작 시각, 종료 시각, 소요 시간 | 시작 항목 저장 시점과 관측 종료 시점 |
| 종료 코드·신호·시작 오류 코드 | 직접 실행한 프로세스의 결과 |
| 관측한 출력 크기, 스트림별 앞 1MiB의 해시·해시 범위 | 출력 원문은 미보관. 해시 대상 크기를 전체 크기로 오해하지 않음 |

`source: local_runner`는 직접 실행기를 통해 관측했다는 출처다. **코드 0은 정상 종료일 뿐**
테스트 항목의 충분성·배포·기능의 현재 정상 동작을 보증하지 않는다. AI가 실패를 무시하는
명령을 실행할 수도 있다. 어떤 명령을 승인하고 실행했는지는 작업 맥락과 함께 판단한다.
원문 출력이 필요하면 사용자 허용 범위에서 일반 터미널 실행으로 별도 확인한다.

## 화면과 AI 조회

작업 상세 상단의 **직접 실행 관측**에는 정상·비정상 종료, 시작 실패, 시간 제한,
중단, 종료 관측 없음이 표시된다. 기존 **기록 타임라인**과 AI 검사 보고는 그대로 보존한다.
실행이 20건을 넘으면 더 보기로 조회한다. 기능 화면에는 연결된 관측 수가 표시되며,
원문은 연결 작업에서 읽는다. 기능 상태를 자동으로 검증 완료로 바꾸지 않는다.

새 MCP 연결에서 `memory_list_executions(project_id, run_id, offset?)`로 같은 결과를 읽는다.
이 도구는 조회 전용이며 프로젝트·저장소·환경 경계를 지킨다. 전체 작업 관측과 특정
기록에 직접 연결한 관측은 별개다. 기존 AI 본문·당시/소급 분류·검증 상태를 덮어쓰지 않는다.

## 중단·실패·이전

- 시간 제한·정상 중단은 실행기가 만든 프로세스 그룹에 종료 신호를 보내고 필요 시
  강제 종료한다. 종료된 부모의 조용한 하위 프로세스도 종료 단계를 생략하지 않는다.
  별도 세션으로 이탈한 하위 프로세스나 외부 작업까지 통제·수집한다고 보장하지 않는다.
- 출력 스트림을 끝까지 확인하지 못하면 `output_complete: 0`이다. 크기와 해시는 관측 범위다.
- 실행기가 강제 종료되거나 종료 저장이 실패하면 시작 항목은 `unconfirmed`로 남는다.
  **실행 중·미실행·실패 어느 쪽으로도 단정하지 않는다.** 원래 종료 결과가 보관돼 있다고
  주장하지 않으며, 저장 재시도를 위해 명령을 다시 실행하지 않는다. 자동 재생·별도 파일 일지는 없다.
- v6 이전은 새 실행 테이블과 인덱스를 추가한다. 기존 본문·ID·영수증·상태는 보존한다.
  구버전 DB의 읽기 전용 화면은 이전하지 않고 실행 목록을 빈 목록으로 표시한다.
  v6 DB에는 새 런타임을 사용한다. 이전 실행 파일로 자동 다운그레이드하지 않는다.
- 전체 백업·복원과 프로젝트 내보내기·가져오기는 관측을 함께 보존한다. 기존 v4/v5 자료의
  원본을 바꾸지 않으며 새 가져오기 대상만 v6으로 확장한다. 가져온 출처 역시 인증된 증명이 아니다.

자동 수집 전체를 뜻하지 않는다. 실행기를 거치지 않은 명령, 서버에 도착하지 않은 호출,
운영체제 강제 종료의 누락 수는 여전히 알 수 없다. 현재 일반 훅 이벤트 수집은 미설치다.

# 로컬 실행 결과 수집

## 수집 범위

Skilly는 명시적으로 실행기를 거친 **프로세스 관측**을 AI 보고와 분리해서 저장한다.
명령·인자·결과를 JSON으로 받아 실행 사실로 등록하는 MCP 쓰기 도구는 제공하지 않는다.
조회 도구 `memory_list_executions`와 기존 기록의 `memory_get_evidence.executions`로 읽는다.
로컬 파일·가져온 묶음은 변조 가능한 자료이므로 이 출처는 암호학적 인증이나 기능 검증이 아니다.

원격 D1도 호스트 전용 수집기와 읽기 전용 MCP 조회를 분리한다. 승인된 호스트가
`CloudExecutionCollector`를 연결하며, AI가 종료 코드·검사 상세를 제출하는 쓰기 도구는 없다.
실제 계정/배포 없이 테스트 D1에서 검증하는 범위와 중복 실행 방지·저장 재시도 계약은
[원격 실행 수집](cloud-mcp.md#호스트의-실행-수집과-원격-조회)을 따른다. 기존 로컬 CLI 경로는 유지한다.

2026-10-22 [공식 Codex Hooks 문서](https://learn.chatgpt.com/docs/hooks)에서
`PostToolUse`와 Bash/unified exec 결과 경로, 프로젝트·훅 정의별 신뢰가 필요함을 확인했다.
설치된 CLI `0.163.0-alpha.10.2`의 `features list`도 `hooks stable true`를 표시했다.
지원 표시는 실제 훅 설치·승인·이벤트 수집 성공과 다르다. 이 기능은 훅·신뢰·사용자 설정을
수정하지 않는다. 일반 도구 호출 전체나 대화·환경 파일·전사 파일을 읽지 않는다.

## 실행 순서

평소처럼 MCP로 프로젝트를 식별하고 작업을 시작한다. 받은 작업 ID와 기존 변경 기록 ID를
사용해 승인된 로컬 검사 명령을 실행한다. DB 경로를 모르면 사적 설정을 읽거나 추측하지 않는다.
이 실행기는 MCP 장애나 신뢰 결정을 우회하는 기록 경로가 아니다.

```sh
npm run build
node dist/runtime/local/main.js exec \
  --db /absolute/test/memory.sqlite \
  --project /absolute/test/project \
  --run-id 작업_UUID --record-id 변경기록_UUID \
  --timeout-ms 60000 -- node --test tests/example.test.mjs
```

`--record-id`는 생략할 수 있으며, 있으면 같은 프로젝트·작업에 속해야 한다.
프로젝트 식별 파일의 저장소·환경과 작업 범위를 대조하고 작업이 열려 있는지 확인한다.
**시작 항목 저장이 성공한 뒤** 지정 프로젝트 폴더에서 명령을 직접 실행한다. 셸 해석은 하지 않는다.
명령 실행 권한이나 네트워크 권한을 새로 부여하는 도구가 아니며 호출한 환경의 권한을 따른다.
현재 macOS/Linux를 지원한다. Windows와 Codex 훅 자동 설치는 포함하지 않는다.

실행기는 자식 표준 출력·오류를 터미널에 재출력하거나 DB에 보관하지 않는다.
실행 영수증 JSON만 출력하며 기본 제한은 60초, 선택 범위는 10ms–1시간이다.
명령 종료 코드를 반환하고 시작 실패는 127, 시간 제한은 124, 사용자 중단은 130이다.
장기 실행 서버를 관리하는 명령으로 사용하지 않는다.

## 저장하는 사실과 저장하지 않는 정보

| 저장 | 의미 |
|---|---|
| 실행·프로젝트·작업 ID, 선택한 기록 ID | 실행 관측과 AI 보고의 연결 |
| 실행 파일의 짧은 이름, 명령 해시 | 인자·절대 경로·환경 원문은 미보관 |
| 시작 시각, 종료 시각, 소요 시간 | 시작 항목 저장 시점과 관측 종료 시점 |
| 종료 코드·신호·시작 오류 코드 | 직접 실행한 프로세스의 결과 |
| 관측한 출력 크기, 스트림별 앞 1MiB의 해시·해시 범위 | 출력 원문은 미보관. 해시 대상 크기를 전체 크기로 오해하지 않음 |

`source: local_runner`는 직접 실행기를 통해 관측했다는 출처다. **코드 0은 정상 종료일 뿐**
테스트 항목의 충분성·배포·기능의 현재 정상 동작을 보증하지 않는다. AI가 실패를 무시하는
명령을 실행할 수도 있다. 어떤 명령을 승인하고 실행했는지는 작업 맥락과 함께 판단한다.
원문 출력이 필요하면 사용자 허용 범위에서 일반 터미널 실행으로 별도 확인한다.

## 화면과 AI 조회

작업 상세 상단의 **직접 실행 관측**에는 정상·비정상 종료, 시작 실패, 시간 제한,
중단, 종료 관측 없음이 표시된다. 기존 **기록 타임라인**과 AI 검사 보고는 그대로 보존한다.
실행이 20건을 넘으면 더 보기로 조회한다. 기능 화면에는 연결된 관측 수가 표시되며,
원문은 연결 작업에서 읽는다. 기능 상태를 자동으로 검증 완료로 바꾸지 않는다.

새 MCP 연결에서 `memory_list_executions(project_id, run_id, offset?)`로 같은 결과를 읽는다.
이 도구는 조회 전용이며 프로젝트·저장소·환경 경계를 지킨다. 전체 작업 관측과 특정
기록에 직접 연결한 관측은 별개다. 기존 AI 본문·당시/소급 분류·검증 상태를 덮어쓰지 않는다.

## 중단·실패·이전

- 시간 제한·정상 중단은 실행기가 만든 프로세스 그룹에 종료 신호를 보내고 필요 시
  강제 종료한다. 종료된 부모의 조용한 하위 프로세스도 종료 단계를 생략하지 않는다.
  별도 세션으로 이탈한 하위 프로세스나 외부 작업까지 통제·수집한다고 보장하지 않는다.
- 출력 스트림을 끝까지 확인하지 못하면 `output_complete: 0`이다. 크기와 해시는 관측 범위다.
- 실행기가 강제 종료되거나 종료 저장이 실패하면 시작 항목은 `unconfirmed`로 남는다.
  **실행 중·미실행·실패 어느 쪽으로도 단정하지 않는다.** 원래 종료 결과가 보관돼 있다고
  주장하지 않으며, 저장 재시도를 위해 명령을 다시 실행하지 않는다. 자동 재생·별도 파일 일지는 없다.
- v6 이전은 새 실행 테이블과 인덱스를 추가한다. 기존 본문·ID·영수증·상태는 보존한다.
  구버전 DB의 읽기 전용 화면은 이전하지 않고 실행 목록을 빈 목록으로 표시한다.
  v6 DB에는 새 런타임을 사용한다. 이전 실행 파일로 자동 다운그레이드하지 않는다.
- 전체 백업·복원과 프로젝트 내보내기·가져오기는 관측을 함께 보존한다. 기존 v4/v5 자료의
  원본을 바꾸지 않으며 새 가져오기 대상만 v6으로 확장한다. 가져온 출처 역시 인증된 증명이 아니다.

자동 수집 전체를 뜻하지 않는다. 실행기를 거치지 않은 명령, 서버에 도착하지 않은 호출,
운영체제 강제 종료의 누락 수는 여전히 알 수 없다. 현재 일반 훅 이벤트 수집은 미설치다.


## 검사 상세 수집 (v7)

직접 `node --test ...`로 실행하고 현재 Skilly와 같은 Node 실행 파일을 쓰면
로컬 실행기가 전용 리포터를 붙인다. 리포터는 `node:test` 이벤트에서 최종 집계와
실패 이름만 전용 파이프로 전달한다. stdout 문장에서 통과 여부를 추측하지 않는다.
기존 리포터·watch·rerun·only 옵션, npm 스크립트·다른 프레임워크는 바꾸지 않고
상세 미수집으로 남긴다. 프로세스 종료 관측은 계속 저장한다.

`test_details.status=collected`에는 통과·실패·취소·건너뜀·예정·총 테스트·스위트
개수, 실행기 종합 성공 여부, 최대 20개·각 200자의 실패 이름이 있다. 상위 테스트나
스위트도 실패 목록에 포함되므로 목록 길이와 실패 테스트 개수는 다를 수 있다.
생략은 `failures_truncated`로 표시한다. 테스트 이름은 테스트 코드가 제공하는
텍스트이므로 비밀을 넣지 않아야 한다. 오류 메시지·스택·assertion·출력 원문은 저장하지
않는다. 전체 전달은 16KiB로 제한하고 잘못된 집계·제한 초과·중단·최종 집계 누락은
`not_collected` 이유로 구분한다. 이 상태는 통과 0개나 검사 성공을 뜻하지 않는다.

기존 실행·원문을 수정하지 않는 v7 추가 테이블에 종료 관측과 함께 원자적으로 저장한다.
v6 이전 관측은 `legacy`로 표시하며 소급 해석하지 않는다. MCP의 실행 조회 및 연결된
기록 근거, 화면의 직접 실행 관측 카드에서 같은 구조를 읽는다. AI 보고와 독립된
관측이지만 로컬 파일 변조 방지 증명이나 기능 검증 완료를 의미하지 않는다.
전체 백업·프로젝트 내보내기에도 포함되며 v4–v6 자료는 읽기 호환을 유지한다.

## Vitest 3 및 npm 검사

`exec --test-format vitest -- ...`는 설치된 Vitest 3의 공개 `onTestRunEnd` 이벤트를
사용한다. Skilly에는 Vitest 의존성을 설치하지 않는다. 직접 Node로 실행하는
`vitest.mjs run`과 package.json의 test 스크립트가 정확히 `vitest run`인
`npm test`를 지원한다. 원래 reporter 목록을 `--reporter=...`로 명시해야 하며,
목록을 알 수 없으면 실행 전 거절한다. 기본 reporter로 임의 교체하지 않는다.

예: 기존 reporter가 default임을 확인한 프로젝트에서
`skilly exec --db /known/db --project /known/root --run-id UUID --test-format vitest -- npm test -- --reporter=default`.
기존 custom reporter도 원래대로 명시한다. Skilly reporter만 추가하고 설정 파일은
수정하지 않는다. watch·서버·별도 outputFile 모드, 다른 버전/임의 npm 스크립트,
npx 다운로드는 지원하지 않는다. 원래 명령이 허가됐다는 전제가 필요하다.

전용 임시 디렉터리에 제한된 집계 JSON만 기록하고 종료 후 원자적으로 DB에 저장한다.
stdout·npm 안내문·오류 문장에서 결과를 추측하지 않는다. 통과·실패·skip·todo와
스위트 종합 성공을 구분하며, 파일 수집 자체가 실패하면 테스트 수가 0이어도
종합 성공은 false다. 오류 본문과 스택은 보관하지 않는다. 임시 집계만 정리하며
사용자의 설정·기록·원문 파일을 삭제하지 않는다.

## 검사 당시 코드와 현재 코드 비교

DB v8부터 실행기 시작·종료 시 Git HEAD와 작업 트리 상태를 별도 관측으로 보관한다.
`memory_list_executions`와 `memory_get_evidence.executions`의 `code_version`은
`before`, `after`, `current`와 `comparison`을 반환한다. 기존 원문과 실행 결과는 바꾸지 않는다.

| 표시 / status | 조건 |
|---|---|
| 코드 버전 일치 / `same_version` | 같은 커밋의 검사 전·후·현재 공개 소스 지문이 같음. 과거 clean 기록은 기존 Git 메타데이터 비교 유지 |
| 코드 버전 변경 / `changed` | 커밋이 다르거나 수집된 공개 소스 지문이 검사 중 또는 검사 후 달라짐 |
| 코드 버전 비교 불가 / `unknown` | 과거 미수집, 지문 없는 과거 미커밋 기록, 종료 미확인, 제외 파일 변경·수집 한도·불안정한 파일, Git 조회 불가, 범위 불일치 또는 비교 폴더 미지정 |

새 관측의 `worktree`는 `public_source_v1` 정책, 수집 상태, SHA-256, 파일 수·바이트 수·제외 수
또는 수집 불가 이유를 담는다. 공개 소스 확장자와 정해진 빌드 manifest만 대상이다.
추적 파일과 무시되지 않은 새 파일의 경로·실행 권한·내용·삭제 표식을 비교한다.
스테이징만 해도 내용이 같으면 같은 지문이다. 원문·파일 목록·개별 해시는 저장하지 않는다.
환경·인증·키·로컬 설정 이름, 숨김/비공개/생성 디렉터리, Git 무시 파일은 읽지 않는다.
제외 파일 변경이 있으면 공개 코드가 같아도 비교 불가다. 모든 비밀을 자동 식별한다는 보장은 아니다.

전체 목록 2048개, 파일당 1 MiB, 합계 16 MiB, 관측당 1초 검사 한도를 적용한다.
Git 명령에는 별도 제한이 있어 전체 호출 시간이 1초 이내라는 뜻은 아니다.
두 번 읽은 내용·목록이 다르거나 링크·특수 파일·읽기 실패가 있으면 비교를 보류한다.
한 조회 안에서 같은 프로젝트 관측을 공유하며 다음 조회에는 다시 읽는다.
DB v12의 별도 `execution_worktrees` 테이블에 지문을 저장하고 조회할 때만 합친다.
기존 `execution_sources` JSON 형식과 원문은 유지하며 예전 기록에 지문을 소급 생성하지 않는다.
개발 중 생성된 인라인 미리보기 지문은 같은 관측의 별도 테이블로 옮겨 정보 손실 없이 정규화한다.
이미 열린 구버전 MCP는 기존 메타데이터 범위로 계속 읽을 수 있지만 새 지문 비교는 하지 못한다.
새로 시작하는 실행기·화면·MCP·백업 도구는 v12 지원 런타임을 함께 사용해야 한다.

일치는 **세 시점의 제한된 관측 비교**다. 중간 변경 후 되돌림, 제외·무시된 파일,
외부 의존성·실행환경·데이터·코드 정확성은 검증하지 않는다. 부분 테스트 성공도 전체 기능의
성공이 아니다. 항상 `claims_verified: false`이며 기존 지식·AI 보고를 검증 완료로 승격하지 않는다.
`assume-unchanged`·`skip-worktree` 인덱스 항목이 있으면 비교 불가다.
Git 명령은 각 1.5초 한도다. HEAD·루트 응답은 128 KiB, `status`·`ls-files`의
NUL 구분 목록은 2 MiB까지 수집한다. 목록은 마지막 NUL까지 완전해야 하며,
시간·출력 한도 초과나 불완전한 응답을 부분 성공으로 사용하지 않는다.
이 목록 한도는 위 공개 소스 내용 수집 한도를 늘리거나 제외 파일 변경을 무시하지 않는다.
출력·경로·파일 본문·diff·원격
주소·환경 파일을 보관하지 않는다. 공개 소스 본문은 지문 계산에만 잠시 읽으며 환경·인증 파일은 읽지 않는다.
프로젝트 루트의 SHA-256은 경로 연결용이며 내용 해시가 아니다.
조회 때 명시된 프로젝트당 현재 관측을 한 번 수행하며 백그라운드 감시는 없다.

MCP는 시작할 때 설정한 `--project /absolute/project`만 비교한다. 화면 서버는 별도로 지정한다.
DB·HTTP·가져온 문서/스킬 경로는 Git 실행 대상으로 사용하지 않는다.

```sh
npm run viewer -- restart-code --db /absolute/memory.sqlite --project /absolute/project
# 여러 구성요소는 --project 반복 지정 (최대 16개, 경로 JSON 합계 1536 bytes)
```

`restart-code`는 인증·주소와 지정한 비교 루트를 유지한다. 이후 `--project`를 생략하면 기존
루트를 유지한다. 일반 `restart`는 자산과 읽기 연결만 갱신한다. 실행 중인 서버에 루트를
추가하려면 `restart-code`를 사용한다. 직접 실행은 `npm run view -- --db ... --project ...`.
백업·복원·프로젝트 내보내기·가져오기는 당시 관측을 그대로 유지한다. 가져온 자료만으로 현재
폴더를 신뢰하지 않으므로 옮긴 경로는 새 실행 관측과 명시적 설정이 필요하다.

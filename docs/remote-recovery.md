# 원격 저장 실패 복구

## 제공 범위

원격 MCP 서버의 영수증과 별도로, 명시적으로 연결한 Node 호스트가 원래 업무 요청을
전용 로컬 SQLite 보관함에 먼저 저장한다. `RemoteWriteRecovery`는 상시 실행 서비스가 아닌
호스트 호출 API다. `remote-serve`는 이 API를 일반 MCP 도구 호출에 연결하며, 상태 화면과
조회·복구 도구를 제공한다. 실사용 Codex 설정·서버·DB에는 자동 적용하지 않는다.
계정 로그인, 토큰 발급/자동 갱신, 원격 명령 재실행과 배포는 포함하지 않는다.

지원 업무는 작업 시작·기록·종료, 계획 저장/항목 갱신, 작업 이벤트 연결, 스킬 등록·설치 지정·
사용 보고다. 실행 수집기의 시작/종료 관측과 이벤트 수신 원문은 지원하지 않는다.
관측하지 못한 요청·이벤트의 누락 개수는 알 수 없다. 원문 보관 성공은 원격 저장 성공과 다르다.

## 상태와 의미

| state | 사용자에게 설명할 의미 |
|---|---|
| recovery_pending | 원래 요청을 로컬에 보관했지만 원격 저장은 아직 확인하지 못함 |
| persistence_unknown | 쓰기를 제출했으나 결과를 확인하지 못함; 이미 저장됐을 수 있음 |
| auth_required | 새 유효 인증이 필요함; 원래 요청은 보관 중 |
| access_denied | 현재 인증 주체에 필요한 권한이 없음; 원래 요청은 보관 중 |
| blocked | 문맥 변경·원문 충돌 등으로 같은 요청의 안전한 자동 재시도를 중단함 |
| saved | 같은 원문·키에 대한 정상 업무 영수증까지 확인함 |

`remote_persistence`는 별도로 `persisted / unknown / not_confirmed`를 반환한다.
인증 만료 상태여도 그 전에 쓰기를 제출했다면 `unknown`을 유지한다.
`remote_saved=false`는 미저장을 증명하지 않는다. `receipt_seen=true`도 같은 키를 찾았다는
뜻일 뿐 같은 원문을 저장했다는 확인은 아니다. 모든 결과는 `claims_verified=false`다.
저장된 보고의 정확성, 검사 성공, 실제 스킬 실행 여부를 이 복구로 검증하지 않는다.

## 호스트 연결 순서

1. 서버는 `createCloudMcpHandler` 설정의 `storage_identity`를 고정한다. 이 값은
   인증 주체와 정확한 project/repository/environment를 함께 식별하는 호스트 계약의 일부다.
   서로 다른 DB binding에 같은 호스트 식별자를 재사용하지 않는다. 이전/복원된 DB는
   native store ID와 쓰기 세대도 확인한다. 오래된 제어 스키마에는 native ID가 없으므로
   호스트 식별자에 의존한다. 생략하면 기존 MCP 도구는 계속 동작하지만 고정표 조회는 거절한다.
2. 명시적 절대 경로에 `SqliteRemoteOutbox(path, destination)`를 연다. 운영 메모리 DB를
   지정하지 않는다. 기존 외부 DB, 다른 endpoint/scope, 심볼릭 링크, 비공개 권한이 아닌
   파일은 거절하며 기존 데이터를 교체하지 않는다. 새 파일은 권한 `0600`이다.
3. `CloudMcpConnection(destination, credential)`을 만든다. credential은 호출마다 새 인증을
   메모리에서 제공하는 비동기 함수다. 모듈은 인증 파일을 읽거나 토큰을 보관하지 않는다.
   endpoint는 정확한 프로젝트 HTTPS 주소 또는 명시적 loopback 테스트 주소만 허용한다.
4. `RemoteWriteRecovery(store, connection, enabled)`를 만든다. enabled는 현재 사용자가
   기록을 허용했는지를 동기적으로 반환한다. 철회 후 추가 전송이나 저장 확인 처리를 하지 않는다.
   이미 제출한 서버 쓰기를 취소/되돌린다는 뜻은 아니다.
5. 온라인에서 `prepare(operation)`으로 문맥 고정표를 얻는다. 서버 인증 주체·scope·저장소·
   쓰기 세대와 필요한 root/session을 묶는다. 이 값은 권한 증명서가 아니며 매 요청마다
   JWT/최신 권한을 다시 검사한다. **고정표를 한 번도 받지 못한 최초 오프라인 상태에서는
   보관함 접수를 성공했다고 표시할 수 없다.**
6. 같은 종류의 업무 명령과 고정표를 `enqueue(command, ticket)`에 넘긴다. 동기 반환된
   `request_id`와 `local_retained=true`가 실제 보관 영수증이다. 실패하면 전송하지 않는다.
   `submit`은 이 보관 다음에 한 번의 복구를 호출하는 편의 API다.
7. `recover([request_id])`를 호출한다. 생략하면 재시도 시각이 된 최대 3건을 선택한다.
   호스트 재시작 시에도 같은 DB/목적지와 새 credential callback으로 다시 열어 이어간다.
   타이머·자동 로그인·백그라운드 전송은 없다. `status(offset)`으로 20건씩 확인한다.

## 일반 MCP 연결과 상태 화면

명시적으로 선택한 원격 연결에만 다음 실행 경로를 사용한다. 기존 `serve`와 로컬 메모리 DB는
그대로 유지한다. 아래 값은 형식 예시다. 실제 계정 연결이나 설정 적용을 대신하지 않는다.

```text
node /absolute/skilly/dist/runtime/local/main.js remote-serve
  --endpoint https://example.invalid/v1/projects/<project-UUID>/mcp
  --project-id <project-UUID> --repository web --environment development
  --outbox /absolute/private/remote.sqlite --credential-env SKILLY_ACCESS_ASSERTION
  --viewer-port 0
```

명시한 `SKILLY_` 환경 변수의 인증값은 호스트 프로세스가 매 요청마다 메모리에서 공급한다.
다른 인증 파일/설정을 읽거나 키를 화면·SQLite·프로젝트 파일에 저장하지 않는다.
부모 환경의 값이 바뀌어도 이미 실행 중인 자식 프로세스의 환경은 자동 변경되지 않는다.
갱신된 인증으로 같은 인자의 MCP 호스트를 다시 시작하면 원래 보관함을 재사용한다.
이 문서나 요청 원문에 인증값을 넣지 않는다.

AI 클라이언트는 이 명령의 stdio MCP에 연결한다. 로컬에 고정한 원격 도구 27개와
`memory_remote_recovery_status`, `memory_recover_remote_writes` 두 도구만 제공한다.
서버가 추가한 이름이나 readOnlyHint로 쓰기 여부를 바꾸지 않는다. 읽기도 고정 scope를 강제한다.

일반 `memory_begin_task`·`memory_checkpoint`·`memory_finish_task` 등에 별도 기록 지시가
필요한 것은 아니다. 이 도구들의 입력이 실제로 중계에 도달하면 보관 후 전송한다.
중계는 어떤 작업을 할지 판단하거나 AI 대신 작업 기록을 작성하지 않는다. 기존 스킬이
일반 작업 중 도구를 호출해야 하며 호출되지 않은 내용의 누락을 이 경로가 감지하지는 못한다.

- 정상 저장은 원래 업무 응답의 `status=persisted`와 실제 run/record ID를 반환한다.
- 보관됐지만 확인하지 못하면 `save_unconfirmed`, `local_retained=true`, 실제 `request_id`를
  오류 응답으로 준다. 큐 ID로 작업 ID를 만들지 않는다. 로컬 보관 실패는 `not_retained`다.
- 저장은 확인됐지만 원래 전체 영수증을 재조회하지 못하면 `saved_response_unavailable`이다.
  기존 저장 확인은 유지하며 임의의 대체 업무 응답을 만들지 않는다.
- 첫 일반 조회 연결은 현재 인증/범위를 확인한 뒤 전송 시각이 된 최대 3건을 복구한다.
  같은 키/입력의 일반 쓰기 재시도도 이미 보관한 요청의 원래 고정표를 사용한다.
- 온라인에서 받은 종류별 고정표는 보관함 v2에 저장한다. v1은 기존 요청/원문/목적지를
  유지하며 추가 테이블로 이행한다. 최초 온라인 고정표가 없으면 오프라인 접수는 여전히 불가능하다.
- `SKILLY_RECORDING=off`면 이후 전송/복구/신규 접수를 막고 보관 상태 조회만 허용한다.

`--viewer-port 0`을 명시하면 같은 호스트 수명 동안만 별도 loopback 상태 화면을 연다.
stderr에 표시한 전체 URL의 로컬 인증은 원격 인증키와 별개다. 일반 브라우저에서도 열 수 있다.
보관함 열기에는 정확한 절대 경로가 필요하지만 브라우저는 경로·endpoint·계정·인증값을
선택/입력할 수 없다. UI는 원문 대신 상태·시각·요청 ID·저장된 근거 ID만 표시한다.

화면의 **새로고침**과 15초 자동 조회는 로컬 상태만 읽는다. **대기 요청 복구** 또는
각 요청의 **다시 확인**만 원래 원격 요청을 보낸다. 인증 만료 요청도 이전에 쓰기를 제출했다면
저장 여부 미확인을 함께 표시한다. 원문을 자동 수정하거나 차단을 해제하지 않는다.

기존 로컬 화면에는 호스트가 `startViewer({db, remoteRecovery: session})`를 명시적으로
주입할 수 있다. 그때에만 **원격 저장** 버튼이 표시된다. 기존 로컬 화면/설정은 자동 전환하지
않으며, 주입하지 않은 화면은 원격 보관함을 만들거나 읽지 않는다.

복구는 원래 고정표를 붙여 영수증을 조회한 다음, **보관한 동일 입력·동일 키**를 다시 제출한다.
서버의 기존 해시/영수증 계약이 중복 생성을 막고 다른 원문이면 충돌로 거절한다.
고정표는 업무 입력 해시에 섞지 않는다. 키·기대 버전·대상 ID·주체·root/session을 자동으로
고쳐 보내지 않는다. endpoint나 계정·저장소가 바뀌면 기존 요청을 새 대상으로 돌리지 않는다.

정상 JSON-RPC 성공만으로 완료하지 않는다. 실제 업무 영수증의 scope와 종류별 ID/버전을
검사한 뒤 로컬 상태를 `saved`로 바꾼다. 확인 전 앱 종료, 응답 유실, 로컬 확인 쓰기 실패는
원문을 남기며 다음 복구에서 같은 기록을 확인한다. 저장 확인 후 중복 보관 payload는 해제하고
키·원문 해시·고정표·최종 상태·작은 영수증 요약은 남긴다. 전체 상태 전이 이력은 제공하지 않는다.
원격 원문과 기존 기록은 수정/삭제하지 않는다.

## 제한과 경합

- 보관함당 미확인 원문 100건/합계 1MiB, 전체 요청 메타데이터 1000건이다.
  꽉 차면 신규 접수를 거절하며 이전 요청을 버리지 않는다. 원문도 64KiB 원격 전송 한도를
  넘지 않아야 한다. 자동 정리/보관함 순환은 아직 없다.
- 한 복구 주기는 기본 30초, 최대 60초이고 개별 HTTP 요청은 기본 5초/최대 30초다.
  인증 공급·헤더·응답 body 대기까지 제한한다. 응답은 최대 64KiB이며 redirect는 거절한다.
  취소를 무시한 credential/fetch Promise도 실제 종료 전까지 4개 한도에 포함한다.
- 일시 오류 재시도 시각은 1–60초로 제한하고 첫 오류에서 해당 주기를 끝낸다.
  인증·권한 실패는 원래 요청을 보존하고 새 인증/권한의 명시적 복구를 기다린다.
- 요청별 lease는 120초다. 작업자가 종료돼도 만료 후 같은 원문으로 재개할 수 있다.
  이전 작업자의 늦은 응답은 새 lease 소유자의 상태를 덮어쓰지 못한다. 로컬 시계 변화가
  복구 지연에 영향을 줄 수 있지만 중복 방지는 서버 영수증/입력 해시로 유지한다.
- 로컬 SQLite 접근 자체가 실패하면 접수/상태 갱신을 보장하지 않는다. 오류를 성공 큐로
  바꾸거나 다른 DB로 우회하지 않는다. 로컬 파일은 악의적 변조에 대한 증명서가 아니다.

## 로컬 검증

`npm run test:cloud`에 `tests/remote-outbox.test.mjs`가 포함된다. 실제 loopback HTTP →
Miniflare/workerd → 테스트 D1에서 저장하고 별도 로컬 보관함을 닫았다 열어 재연결한다.
응답 유실·인증 만료·권한 철회·다른 사용자/DB/쓰기 세대/root/session·동시 복구·lease 만료·
로컬 확인 실패·불완전한 영수증·기록 철회·용량 및 시간 제한을 주입한다.
`tests/remote-host.test.mjs`는 SDK Client → 별도 `remote-serve` 프로세스 → loopback HTTP →
테스트 D1의 일반 작업 저장과 보관 실패/응답 유실/인증 만료, 새 MCP 프로세스 재조회를 확인한다.
상태 API의 무인증/교차 Origin 차단과 GET의 무전송, 기존 viewer의 명시적 주입도 검사한다.
Worker 외부 요청은 차단한다. 실제 계정/공개 인터넷 연결/실사용 Codex 설정 로딩의 검증은
아니며 테스트 저장 영수증은 AI 보고를 직접 관측으로 승격하지 않는다.

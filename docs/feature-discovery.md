# 기능 찾기와 명시적 분류

기능 이름·ID·설명, AI가 명시적으로 등록한 별칭과 코드 경로로 기능과 이미 연결된 작업을
찾는다. 검색은 읽기 전용이다. 과거 미분류 작업을 제목이나 파일 이름으로 추정해 연결하지 않는다.
같은 별칭의 기능은 모두 후보로 반환하며 자동 선택하지 않는다.

## 등록과 범위

새 MCP의 `memory_begin_task` 또는 `memory_checkpoint`의 기존 `features` 선언에
선택 필드 `aliases`, `code_paths`를 함께 전달한다. 사용자에게 별도 DB 관리 작업을 요구하지 않는다.

```json
{"key":"comment-resolution","name":"댓글 해결","aliases":["해결 처리","대화 완료"],"code_paths":["src/reviews/comments"]}
```

각 배열은 요청당 최대 8개, 기능·저장소·환경별 누적 64개다. 생략·빈 배열은 기존 정보를 지우지 않는다.
원래 요청의 재시도에는 메타데이터를 추가하지 않는다. 새로운 선언은 새 멱등 키를 사용한다.
등록은 작업·보고·영수증과 같은 트랜잭션에 포함되며 출처 작업 ID를 보존한다.
기능 이름과 기존 정의는 충돌 시 덮어쓰지 않는다. 기존 완료 작업이나 원문을 다시 쓰지 않는다.

별칭·경로는 출처 작업의 실제 저장소·환경 범위에 저장한다. MCP는 기본적으로 연결된 저장소 범위이며,
서비스 전체 조회는 명시적 `coverage: "service"`를 사용한다. 화면의 기능 검색은 선택 프로젝트 전체 범위다.
프로젝트·저장소·환경·구성요소·기능 필터는 검색과 함께 적용되며 검색을 이유로 범위를 넓히지 않는다.

경로는 저장소 상대 경로다. 역슬래시·선행 `./`는 정규화하며 절대 경로·상위 이동·명백한 비밀 경로는 거부한다.
파일을 읽거나 폴더를 스캔하지 않는다. `src/web`는 `src/web/a.ts`에 일치하지만 `src/web-other`에는 일치하지 않는다.
등록 디렉터리 아래의 파일 경로로도 찾을 수 있다. 파일명 일부만을 해석하는 퍼지 검색은 없다.

## 조회와 화면

`memory_query_overview`에 `view: "features"`, `query: "해결 처리"`를 주면 기능 후보를,
`view: "tasks"`에 같은 검색어를 주면 기존 기능 연결을 가진 작업을 찾는다.
작업 제목·요청·저장소의 기존 검색도 유지한다. 검색 조건은 페이지 제한 전에 적용한다.

결과의 `match_reasons`는 종류·읽기 쉬운 이유·일치 값·기능 ID를 제공한다. 등록 정보는
저장소·환경·출처 작업도 포함한다. `discovery`는 기능당 별칭과 경로를 각각 최대 8개 표시하며
생략 여부를 알려준다. 검색 자체는 표시되지 않은 등록 정보도 대상으로 한다.
응답 크기 제한과 기존 페이지 이동을 유지하며 큰 항목은 명시적으로 생략 표시한다.

상세보기 → **기능**에서 이름·별칭·경로로 검색하고 이유를 확인한 뒤 기능을 선택한다.
상세의 **연결 작업 보기**로 이어진다. 작업 탭의 검색도 별칭·경로와 매칭 이유를 지원한다.
기능 검색과 기존 대시보드·구성요소 카탈로그의 전체 요약은 분리된다.
빈 결과는 기능 부재·명령 미실행·기록 완전성을 증명하지 않는다.

## 저장과 검증의 의미

DB v10은 기존 자료를 보존하고 별칭·경로 테이블과 범위별 인덱스만 추가한다. 옛 DB는 읽기만으로
마이그레이션하지 않으며 이름·기존 작업 검색을 계속 지원한다. 전체 백업과 단일 프로젝트 교환에
등록 정보·출처 연결을 포함하고 가져오기 시 범위·참조·형식을 검증한다.

이름·별칭 부분 검색은 해당 범위의 후보를 읽을 수 있다. 벡터 검색·의미 유사도 모델·전역 파일 감시기는 없다.
원문 FTS와 등록 정보의 범위 인덱스는 유지하지만 큰 DB에서 일정한 응답 시간을 보장하지 않는다.
코드 경로와 별칭은 `explicit_feature_metadata`이며 AI의 선언이다. 실제 코드·테스트·배포 검증으로 승격하지 않는다.

새 DB 버전을 읽지 못하는 이전 관리 서버는 `degraded`가 될 수 있다. `restart-code`는 현재 코드로
DB와 자산을 먼저 점검한 뒤에만 기존 주소·인증을 유지해 교체한다. 사전 점검 실패 시 기존 서버를 보존한다.

## 로컬 D1 어댑터

D1의 명시적 `007-feature-discovery.sql` 적용 후 `D1FeatureReader.list`와
`D1TaskReader.listTasks({query})`에서 별칭·코드 경로 후보와 매칭 이유를 조회한다.
메타데이터 저장에는 활성 작업과 범위가 필요하며 기존 미분류 기록은 그대로 보존한다.
006 이하의 이름 검색은 유지하고 메타데이터 미지원 여부를 명시한다. D1 비동기
조회·revision 확인의 범위는 [저장 계약](cloud-storage-contract.md#기능-검색과-현재-지식-통합-조회)을
참고한다. 기존 로컬 MCP/화면의 SQLite 경로를 변경하는 기능은 아니다.

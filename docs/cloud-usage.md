# 개인 클라우드 사용량 예산

이 기능은 Skilly 원격 MCP의 과도한 요청을 제한한다. Cloudflare 계정의 무료 요금제,
비용 0원 또는 실제 디스크 용량을 보증하는 기능은 아니다. 계정 연결·배포·요금제
변경·다른 DB로의 자동 쓰기 전환은 하지 않는다.

## 명시적인 호스트 설정

테스트/신규 D1에 기존 001–011 뒤 `012-usage-budget.sql`을 명시적으로 적용하고,
`D1UsageBudget.install(policy)`로 DB당 하나의 정책을 등록한다. 정책 설치는 호스트
전용 API이며 MCP 도구·요청 본문·헤더로 정책이나 사용자 식별자를 선택할 수 없다.
동일 정책 재설치는 멱등적이고, 다른 정책으로 조용히 교체하지 않는다.
정책 변경과 예약 복구는 아래의 별도 운영 API를 통해서만 처리한다.

```ts
const policy = {
 daily: { requests: 1000, batches: 1000, rows_read: 1000000, rows_written: 20000 },
 user_daily: { requests: 500, batches: 500, rows_read: 500000, rows_written: 10000 },
 request: { batches: 8, statements: 256, rows_read: 10000, rows_written: 200 },
 accepted_write_bytes: 16 * 1024 * 1024,
};
await new D1UsageBudget(testDb).install(policy);
const handler = createCloudMcpHandler(testDb, {
 endpoint, policy_id, scope, storage_identity, usage_protection: true,
});
```

위 숫자는 설명용 애플리케이션 예산이며 공급자의 무료 한도가 아니다. 각 요청 예약은
DB 전체와 사용자 일일 예산에 모두 들어맞아야 한다. 보호가 설정됐는데 스키마·정책·
예약 저장을 확인할 수 없으면 503 `usage_unavailable`이며 무제한 처리로 전환하지 않는다.
기존 연결의 설정·DB는 자동으로 바꾸지 않는다. `usage_protection`을 생략한 기존 연결은
종전 동작을 유지하므로 보호가 적용됐다고 표시하면 안 된다.

## 예약·관측·정산

1. 인증용 D1 조회 전에 DB 전체 예산에서 요청 1회와 요청별 최대 배치·읽기/쓰기 행 수를
   예약한다. 인증 실패도 DB 전체 요청량을 소비한다.
2. 인증과 고정 프로젝트 접근 확인 후, 검증된 issuer/subject의 해시를 기준으로 사용자
   예산을 추가 예약한다. 키 변경·새 연결·프로젝트 변경으로 같은 사용자의 예산이 초기화되지 않는다.
3. 인증 정책·권한 재확인을 포함한 실제 D1 업무 경로의 `rows_read`·`rows_written`을 수집한다.
   SQL 호출 수와 배치 수도 제한한다. 누락된 meta를 0으로 만들지 않는다.
4. 모든 native D1 호출이 끝나면 미사용 예약만 원자적으로 반환한다. 요청 수는 반환하지 않는다.
   동시에 들어온 다른 연결도 공유 예약을 보므로 각자의 로컬 카운터만 보고 초과 승인하지 않는다.
5. 쓰기 도구 실행 전 요청 JSON의 UTF-8 바이트를 별도의 누적 예산에 더한다. 이 값은
   **수락한 쓰기 요청 바이트**다. 실제 DB 파일 크기·순수 신규 저장량이 아니다.
   멱등 재시도·권한/입력 검사에서 거절된 시도도 보수적으로 소비할 수 있으며 자동 환불하지 않는다.
   동일 키의 업무 원문은 기존 멱등 계약으로 한 번만 저장한다.

`cloud_usage_reservations`는 `held`(예약 중), `settled`(관측 정산),
`uncertain`(계량 확인 불가)을 구분한다. 호스트 전용 `snapshot()`은 제한된 최근 내역과
집계만 읽으며, 일반 MCP 사용자에게 다른 사용자의 잔액·신원을 공개하지 않는다.
요청 본문·인증키는 예산 테이블에 저장하지 않는다. 기존 원문/작업 이력은 수정하지 않는다.

## 초과와 복구

- 예산이 부족하면 429 `usage_limit`과 `Retry-After`를 반환하며 업무 쓰기를 시작하지 않는다.
  이미 쓰기를 제출한 뒤 오류가 난 경우에는 `delivery.persistence: unknown`으로 구분한다.
- UTC 일일 예산은 새 구간에서 다시 시작한다. 누적 쓰기 바이트는 날짜가 바뀌어도 반환되지 않는다.
  누적 상한을 올리거나 정책을 교체하려면 별도 운영 미리보기와 명시적인 적용이 필요하다.
- 저장 응답 유실·SQL 오류·계량 누락은 전체 예약을 유지하고 해당 구간을 차단한다.
  확인되지 않은 사용량을 환불하거나 성공으로 바꾸지 않는다. 단순 시간 경과로 이전 예약을 지우지 않는다.
- HTTP가 끝나도 native D1이 실행 중이면 예약은 `held`다. 실제 종료가 관측되면 정산할 수 있지만,
  프로세스가 사라지거나 정산 응답을 잃으면 예약이 보수적으로 남을 수 있다.
- 원격 복구 대기열은 원래 키·내용을 보존하고, 서버의 재시도 시각(최대 24시간)을 따른다.
  요청 한도는 영구 입력 오류로 취급하지 않는다. 재연결 후에도 원래 영수증 확인과 동일 입력 재시도로
  업무 저장의 중복을 막는다. 실제로 받지 못한 요청은 보관됐다고 표시하지 않는다.

## 무료 한도와 계량의 경계

D1 행 수는 실행 **후** 관측된다. 하나의 SQL이 예상보다 많은 행을 읽으면 이미 발생한
비용을 취소할 수 없다. 예약량 초과를 저장하고 다음 호출을 차단하지만 초과분 발생 자체를
보장해서 막지는 못한다. 응답 유실은 실제 사용량을 모를 수 있고 UTC 경계를 넘긴 지연 호출도 있다.
계량 불가 상태를 현재 검사 성공이나 실제 저장 성공으로 간주하지 않는다.

예산 정책 조회·예약·정산 SQL 자체의 비용, 거절 요청의 입구 비용, 다른 Worker/DB,
Workers CPU/요청 수, 인덱스·파일 공간, 직접 관리용 HTTP 접근은 이 집계 밖이다.
외부 계정 사용량을 조회하지 않으므로 실제 남은 무료 한도를 안다고 주장하지 않는다.
예산 이력도 공간을 소비하며 자동 삭제하지 않는다. 배포 전 계정 전체 모니터링과 여유분,
불확실 예약/정책 변경의 운영 절차가 추가로 필요하다.

공식 계약: [D1 요금·집계 기준](https://developers.cloudflare.com/d1/platform/pricing/),
[D1 결과 meta](https://developers.cloudflare.com/d1/worker-api/return-object/).
무료 한도는 UTC 기준으로 갱신되며 읽기/쓰기 행 수와 저장량은 별개다.

## 한도 변경과 예약 복구 운영 API

`013-usage-operations.sql`은 **선택한 테스트/신규 D1에 명시적으로** 적용한다.
원래 012 정책과 기록은 보존하고, 정책 버전·예약별 당시 정책·실행 등록·완료 근거·운영
영수증을 추가한다. 실사용 DB나 SQLite를 자동 업그레이드하지 않는다.
012만 있는 DB의 기존 동작은 유지되지만 운영 API는 지원하지 않는다.

013에는 새 예약의 버전 검사를 요구하는 DB 트리거가 있다. 이전 실행 파일은 신규 예약을
추가하지 못하며 그 요청의 예산 변경도 함께 롤백된다. 먼저 모든 호스트 실행 파일을 갱신해야
한다. 이미 남은 구버전 예약은 그대로 보존하며, 추적 근거 없는 예약의 정산·정책 변경을
강제로 허용하지 않는다. 사용자가 지우거나 원문을 옮겨 해결할 필요는 없다.

다음은 호스트 코드에서 테스트 D1 바인딩을 명시해 호출하는 예시다. 일반 사용자 MCP에는
운영 도구를 추가하지 않는다. DB 바인딩을 가진 신뢰된 호스트만 이 API를 호출한다.

```ts
const ops = new D1UsageOperations(testDb);
const preview = await ops.previewPolicy(candidatePolicy, '다음 요청의 상한 조정');
// preview.status와 변경 값·차단될 접수 범위를 검토한 뒤 같은 입력을 적용한다.
await ops.applyPolicy(candidatePolicy, {
 reason: '다음 요청의 상한 조정', expected_hash: preview.expected_hash,
 idempotency_key: 'policy-change-001',
});
const page = await ops.listReservations({ limit: 20 });
const recovery = await ops.previewRecovery(selectedReservationId);
await ops.recover(selectedReservationId, {
 expected_hash: recovery.expected_hash, idempotency_key: 'reservation-recovery-001',
});
```

### 한도 변경 미리보기

- 미리보기는 조회만 한다. 이전 값·새 값·새 요청이 막힐 예산 범위를 보여 준다.
- 해시는 DB 식별자·정책 버전·공유 사용량 revision·UTC 구간·당시 집계를 포함한다.
  정책이나 사용량이 바뀐 뒤 오래된 해시로 적용하면 `preview_changed`다.
- 적용은 정책 새 버전과 운영 영수증을 같은 D1 배치에 저장한다. 동시 적용은 하나만 성공한다.
  버전 이력을 덮어쓰거나 사용량·차감량·누적 바이트를 초기화하지 않는다.
- 이미 차감한 양보다 한도를 낮출 수 있지만, 추가 접수가 차단될 수 있음을 미리 표시한다.
  기존 예약의 정산은 예약 당시 정책을 사용하고, 신규 예약은 최신 정책을 배치 안에서 확인한다.
- 사용량 범위가 잘렸거나 구버전 미해결 예약이 있으면 불완전한 미리보기를 적용하지 않는다.

### 불확실 예약 조회와 복구

목록은 미해결 예약을 먼저 필터링하고 생성 시각/ID 키셋 페이지로 조회한다. 최신 100개에서
검색하는 방식이 아니므로 오래된 미해결 항목도 찾을 수 있다. `next_cursor`가 있으면 이어서
조회한다. 페이지는 실시간이며 전체 스냅샷이나 누락 0개의 증거가 아니다.

`execution_lease_pending`은 요청 소유자의 실행 등록이다. 첫 실제 D1 호출 전에 한 번 저장하고,
해당 요청의 모든 호출이 끝난 뒤에만 종료를 저장한다. 실제 CPU 실행 여부·실시간 SQL 개수나
프로세스 생존의 증거가 아니다. 프로세스가 사라지거나 종료 저장을 확인하지 못하면 그대로
남는다. 늦게 도착한 준비 응답도 요청 종료 상태를 다시 확인하며 종료 후 새 SQL을 시작하지 않는다.

| 저장 상태 | 복구 동작 | 예산 반환 | 업무 저장 여부 |
|---|---|---|---|
| 종료와 실제 D1 meta가 보존됐지만 정산이 미완료 | 저장된 완료 근거로 정산 재개 | 당시 예약의 미사용분만 | 이 API로 판정하지 않음 |
| 실행 등록이 없거나 종료됐지만 사용량을 확인 못 함 | 추가 실행을 막고 보수적 차감 확정 | 없음 | 확인 불가 유지 |
| 실행 등록 종료를 확인 못 함 | 복구 차단 | 없음 | 확인 불가 유지 |
| 구버전 예약으로 추적 근거가 없음 | 조회만 제공, 복구 차단 | 없음 | 확인 불가 유지 |
| 이미 정산·복구 완료 | 기존 상태/영수증 반환 | 추가 반환 없음 | 원래 업무 영수증으로 별도 조회 |

호출자가 AI 보고의 숫자를 전달해 반환받는 API는 없다. 실제 실행 경계가 보존한 완료 근거를
읽으며 `claims_verified: false`를 유지한다. 요청 수·누적 쓰기 바이트는 반환하지 않는다.
근거가 없는 예약도 시간 경과나 관리자 승인만으로 사용량 0으로 바꾸지 않는다.
다른 미해결 불확실 예약이 남아 있으면 공유 차단을 임의로 해제하지 않는다.

복구는 예약 revision과 실행 등록을 검사하고, 이전 소유자의 추가 실행을 차단한다.
차감·반환·완료 표시·운영 영수증이 같은 배치에 들어가므로 자동 정산과 경합해도 중복 반환하지
않는다. 응답을 잃으면 `getOperation(originalKey)`로 확인하고, 같은 해시·입력·키로 재시도한다.
다른 입력으로 같은 키를 쓰면 충돌이다. 원래 업무 명령을 다시 실행하는 운영 API가 아니다.

운영 SQL 자체도 비용을 소비한다. 무료 요금 보장·계정 전체 계량은 여전히 범위 밖이다.
별도 운영 CLI·일반 사용자 관리 화면·실계정 운영 연결은 이 호스트 API와 구분한다.
`tests/usage-operations.test.mjs`에서 동시 정책 변경, 미리보기 만료, 원래 예약 가격,
정산/운영 응답 유실, 지연 실행, 차단 유지, 구버전 보존과 오래된 미해결 페이지를 검증한다.

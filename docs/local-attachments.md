# 로컬 첨부 원본 보관

작업 상세의 **첨부 원본 → 파일 선택**에서 공개 자료를 선택하고 연결할 기록을 고른 뒤
**원본 보관**을 누른다. 작업 전체에도 연결할 수 있다. 원본 파일이나 기존 작업 보고는
수정하지 않는다. 선택한 파일의 바이트만 전달하며 원래 디스크 경로는 수집하지 않는다.

- 파일당 4 MiB, 프로젝트당 원본 합계 64 MiB, 작업당 연결 500개까지 보관한다.
- 같은 프로젝트의 동일한 바이트는 한 번 저장한다. 이름·작업·기록이 다른 연결은 각각
  유지한다. 같은 대상·이름·내용으로 재시도하면 기존 연결을 반환한다.
- 실패가 표시되면 같은 파일과 같은 연결 대상으로 재시도한다. 저장 확인 전에는 원본을
  보관했다고 판단하지 않는다. 자동 재전송·자동 삭제·보존 기간 만료 기능은 없다.
- 원본 보기·받기는 보관된 크기와 SHA-256을 다시 확인한다. 일치는 보관본 무결성만
  뜻하며, 파일 내용의 정확성·안전성·원래 경로·실제 작업 결과를 검증하지 않는다.
- 텍스트는 문자 그대로 표시하며 앞부분 128 KiB까지 미리 본다. 작은 정적 PNG·JPEG는
  최대 2048 × 2048까지 표시한다. HTML·SVG·애니메이션·PDF·다른 바이너리는 실행하거나
  내장하지 않고 원본 받기로 제공한다. 환경·인증 파일과 개인키로 알려진 이름은 거절한다.

## 용량 표시

**프로젝트 첨부**는 같은 바이트를 중복 계산하지 않은 원본 크기다. **전체 DB**는 모든
프로젝트의 기록·첨부가 들어 있는 DB 파일과 WAL·공유 메모리 파일의 현재 크기다.
파일시스템 크기 조회이며 프로젝트별 실제 디스크 할당량은 아니다.

첨부는 DB 안에 64 KiB 이하 조각의 base64 텍스트로 보관한다. 원본보다 약 1/3 큰
인코딩과 SQLite 색인·저널 공간이 추가로 필요하다. 별도 파일 저장소·상시 스캔·모델·
감시 프로세스는 사용하지 않는다. 목록 조회는 원본 내용을 읽지 않는다.

## 호환성과 백업

조회만으로는 DB를 생성하거나 마이그레이션하지 않는다. v15/v16 DB의 첫 명시적 첨부
저장에만 v17 확장을 같은 트랜잭션으로 적용한다. 연결 대상·권한·이전 쓰기 차단 상태를
먼저 확인한다. 실패하면 확장과 데이터 쓰기를 함께 되돌린다. 이후 모든 로컬 MCP·
화면·관리 명령은 v17을 지원하는 같은 최신 실행 파일을 사용한다. 이전 버전으로 열기
위해 DB 버전 번호를 낮추지 않는다.

전체 DB 백업·복원은 원본과 연결을 함께 보존한다. 로컬 프로젝트 내보내기·가져오기도
선택한 프로젝트의 첨부를 포함하며 내용과 관계를 검증한다. 내보내기의 기존 64 MiB
한도는 **인코딩된 데이터와 다른 기록의 합계**에 적용되므로 첨부 저장 한도와 다르다.
초과하면 완료 번들을 발행하지 않고 오류를 반환한다. 잘라 내거나 원본을 지우지 않는다.
큰 프로젝트는 전체 DB 백업을 사용한다.

v17 SQLite와 D1 사이의 이동은 아직 지원하지 않으며 기존 로컬 연결 경계에서 거절한다.
클라우드에 첨부를 전송하지 않는다. 현재 첨부 쓰기는 인증된 로컬 화면의 명시적 동작으로
제공하며, 일반 기록을 저장하는 AI가 임의로 로컬 파일을 찾아 첨부하지 않는다.

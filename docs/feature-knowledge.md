# 기능별 현재 근거 판정

사용자 선택의 정정·철회·충돌은 [결정과 변경 이력](decisions.md)에서 별도로 다룬다.
검사의 현재성과 사용자 결정의 적용 상태를 서로 검증 완료로 승격하지 않는다.

기능 조회 `memory_query_overview(view: "features")`와 화면의 기능 목록·상세는 같은
`current_knowledge` 파생 결과를 사용한다. 기존 원문·보고·실행 결과는 수정하지 않는다.
DB 마이그레이션이나 현재 상태 포인터 저장 없이 조회 시 평가한다.

| 상태 | 의미 |
|---|---|
| `current` | 현재 Git 버전과 비교 가능한 직접 검사 관측이 있음. 기능 전체 검증이 아님 |
| `stale` | 관측한 코드 버전이 달라 예전 검사를 현재 성공으로 재사용할 수 없음 |
| `conflict` | 같은 저장소·환경·루트·커밋·명령 해시에서 통과와 실패 관측이 모두 있음 |
| `unknown` | AI 보고만 있거나, dirty 코드·비교 경로 미설정·불완전 검사·조회 상한 등으로 판정 불가 |

`current`에도 실패 관측이 있을 수 있다. `counts.passed/failed`, 각 근거의 `result`와 이유를
함께 읽는다. 다른 명령의 성공과 실패는 서로 다른 검사이며 충돌로 합치지 않는다.
동일 조건의 상반된 관측은 최근 성공 하나로 덮지 않는다. 오래된 근거와 현재 근거가 함께
있으면 각각의 수를 표시하며, 비교 불가능한 관측이 섞이면 전체 판정은 미확인으로 유지한다.
상태 우선순위는 확인된 충돌 → 범위 불완전/미확인 → 현재 근거 → 오래된 근거 → 근거 없음이다.

직접 검사 결과는 실행기에서 수집한 Node.js/Vitest 상세와 정상 종료 결과가 서로 맞을 때만
사용한다. 종료 코드 0만 있는 일반 명령, 취소·예정 항목, 출력 불완전, 타임아웃·중단은
현재 검사 성공 근거가 아니다. 건너뛴 검사가 있으면 그 수를 그대로 표시한다.

AI의 구현 상태·검사 보고는 기존 별도 영역에 남는다. `claims_verified`와
`agent_reports_promoted`는 항상 false다. 기능별 근거 판정은 기존 자유 문장 컨텍스트의
`current_knowledge: []`를 확정 지식으로 채우거나 사용자 의사결정을 인증하는 기능이 아니다.

## 범위·상한·출처

프로젝트·저장소·환경·구성요소·기능 필터를 실행 조회 전에 적용한다. 실제 현재 코드 비교는
호스트가 명시적으로 허용한 프로젝트 경로만 사용한다. DB에 저장된 경로나 별칭·보고문을
명령·파일 접근 대상으로 사용하지 않는다. MCP의 bound root와 화면의 sourceProjects가
다르면 실제 비교 가능 범위도 다르므로 결과가 달라질 수 있다.

기능당 최근 40개 실행을 조사하며 41번째가 있으면 `truncated: true`로 전체 판정을
미확인 처리한다. 그 범위 안에서 확인된 충돌은 표시할 수 있다. 원본은 작업별 실행 조회에서
페이지로 확인한다. 응답에는 최근 근거 8개·충돌 묶음 8개·각 충돌 ID 8개만 표시하고
생략 여부를 별도로 알린다. 전체 overview 크기 제한으로 항목 자체가 요약되면 화면은
판정 정보 부재를 미확인으로 표시한다.

각 근거는 실행·작업·연결된 원문 ID, 저장소·환경·커밋, 검사 수, 비교 이유를 가진다.
조회 한 번에서 동일한 루트·프로젝트 키·저장소·환경의 Git 관측은 재사용한다.
현재성은 Git 메타데이터 비교이며 무시된 파일·의존성·실행환경은 검증하지 않는다.
